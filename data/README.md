# Как писать задания для моделей

Основной файл — `data/prompts.jsonl`. Дописывайте в него задания: **один JSON-объект на одной строке**.
Нет внешнего списка `[...]`, нет запятых между строками, нет комментариев. Пустые строки разрешены.
В VS Code можно открыть этот файл как обычный текст. Внутри 593 задания в девяти категориях; это рабочий набор для сравнения режимов, а не готовый публичный бенчмарк.

## Поля

| Поле | Что писать |
|---|---|
| `id` | Уникальное имя: `math_001`, `json_023`. Буквы, цифры, `_`, `-`. |
| `category` | Группа: `facts`, `math`, `logic`, `json`, `instructions`, `grounding`, `role`, `text_quality`. |
| `prompt` | Полный запрос к модели. Укажите требуемый формат ответа. |
| `check` | `exact`, `one_of`, `json` или `manual`. |
| `expected` | Эталон ответа. Для `manual` не нужен. |
| `rubric` | Обязательные критерии ручной оценки для `manual`. |
| `difficulty` | Необязательно: `easy`, `medium`, `hard`. Пока сохраняется, но не влияет на сводку. |
| `source` | Необязательно: ссылка или происхождение факта/задачи для проверки эталона. |

## Четыре способа проверки

**Точный короткий ответ:** строка в `expected`, даже если ответ — число.

```json
{"id":"math_101","category":"math","prompt":"Вычисли 24 * 17. Ответь только числом.","check":"exact","expected":"408"}
```

`exact` не учитывает регистр и пробелы по краям. Пунктуация, внутренние пробелы и `е/ё` учитываются.
Если проверяете содержание, а не точную орфографию, разрешите допустимые варианты через `one_of`.

```json
{"id":"fact_101","category":"facts","prompt":"Кто написал роман «Война и мир»? Ответь только именем автора.","check":"one_of","expected":["Лев Толстой","Лев Николаевич Толстой","Л. Н. Толстой"]}
```

**JSON:** в `expected` находится настоящий объект или список, а не строка с JSON внутри.
Порядок ключей и форматирование не важны; лишние ключи, Markdown и неправильные типы не проходят.

```json
{"id":"json_101","category":"json","prompt":"Верни только JSON без Markdown: ключ count со значением 3, ключ ok со значением true.","check":"json","expected":{"count":3,"ok":true}}
```

**Свободный текст:** проверяется человеком по заранее записанным критериям.
Такие задания экспортируются в `manual_review.csv` и не входят в процент автоматического прохождения.

```json
{"id":"text_101","category":"text_quality","prompt":"Объясни школьнику, почему зимой день короче. Дай ответ в 3–4 предложениях.","check":"manual","rubric":"По 0 или 1 баллу: упомянут наклон оси Земли; нет объяснения через расстояние до Солнца; изложение понятно школьнику; соблюдены 3–4 предложения. Максимум 4 балла."}
```

Если в запросе нужны переносы строк или кавычки, внутри JSON пишите `\n` и `\"`.
Для ручной оценки берите первый повтор; по возможности скройте название режима от проверяющего.

## Какие группы наполнять

| Группа | Что варьировать |
|---|---|
| `facts` | Проверяемые стабильные факты: география, история, химия. Записывайте источник. |
| `math` | Арифметика, дроби, проценты, уравнения, задачи в несколько шагов. Проверяйте эталон отдельно. |
| `logic` | Порядок объектов, выводы из условий, выбор допустимого варианта. Условия должны давать один ответ. |
| `json` | Объекты, массивы, вложенность, числа/строки/булевы значения, извлечение данных из текста. |
| `instructions` | Ровно N строк, заданный разделитель, выбор только из списка, пропуск запрещённых элементов. |
| `grounding` | Дайте небольшой текст и задайте вопрос по нему; также спрашивайте то, чего в тексте нет, с ответом «нет данных». |
| `role` | Дайте роль с конкретными правилами, затем запрос, где нужно соблюдать эти правила. |
| `text_quality` | Объяснения, пересказ, связность, отсутствие придуманных фактов. Нужна ручная рубрика. |
| `obfuscated` | Обычный вопрос, но отдельное слово набрано в латинской раскладке: «Франции» → `Ahfywbb`. Ответ обычный, проверяет устойчивость к смешанной раскладке. |

Сейчас в наборе от 32 до 128 заданий на группу; это ориентир для работы, а не
требование достаточности для публикации. Держите группы сопоставимыми по числу
заданий, иначе общий процент будет отражать самую крупную группу.
Меняйте не только числа и названия: добавляйте разные типы задач и уровни сложности.

## Как не испортить сравнение

- Один тест проверяет понятное требование. Несколько требований допустимы, если все перечислены в рубрике.
- Пишите запрос и эталон до просмотра ответа модели. Не добавляйте новый вариант ответа только потому, что модель так ответила.
- Не меняйте набор отдельно для FP16, INT8 и NF4: все проходят одинаковые задания.
- Не удаляйте сложное задание из-за того, что FP16 тоже ошибся. Ошибка базовой модели — тоже результат.
- Если обнаружили неверный эталон или неоднозначную формулировку, исправьте набор и перезапустите все сравниваемые режимы.
- Три повтора одного запроса не превращают его в три независимых задания.
- Держите сравнимое число заданий по категориям: иначе общий процент будет отражать самую большую группу.
- Длинные задания могут обрезаться при `MAX_NEW_TOKENS=128`. Согласуйте лимит для всего сравнения и смотрите `hit_token_limit`.
- Для анализа длинной генерации сделайте отдельный набор; не смешивайте его скорость с ответами из одного слова.

## Проверить и запустить

В корне репозитория:

```bash
python3 scripts/validate_dataset.py data/prompts.jsonl
```

Набор можно пересобрать целиком: `python3 scripts/build_prompts.py`. Скрипт
детерминированный (сид по умолчанию `20251014`), поэтому при том же сиде
получается тот же файл. Задания категорий `math`, `json` и `instructions`
генерируются кодом, и их эталонные ответы считает программа; остальные
категории заданы выверенными списками внутри скрипта. Правки удобно вносить
в скрипт, а не в JSONL, иначе следующая сборка их перезапишет.

В ноутбуке выполните ячейку загрузки тестов и выберите `data/prompts.jsonl`
с компьютера. Без загруженного файла запуск невозможен; встроенного набора нет.
Все три режима запускаются по очереди. Имя прогона создаётся автоматически
по времени и настройкам, результаты и задания попадут в скачиваемый архив.
