# Влияние агрессивной оптимизации и низкобитной квантизации на качество генерации LLM при локальном инференсе (на примере семейства Qwen2.5)

Исследовательский проект, посвященный оценке падения качества генерации и вычислительной эффективности моделей семейства **Qwen2.5** при переходе к низкобитной квантизации и агрессивным техникам оптимизации инференса.

## Цель исследования
Определить границу («sweet spot») между экономией аппаратных ресурсов (VRAM, задержка) и деградацией генеративных способностей языковой модели в сценариях локального развертывания.

## Исследуемые параметры

### Объект исследования
* Семейство моделей **Qwen2.5** (базовые FP16/BF16 vs квантованные варианты: AWQ, GPTQ, GGUF Q8_0, Q4_K_M, суб-3-bit).

### Критерии оценки
* **Качество текста:** фактологическая корректность, семантическая связность ответов, устойчивость к галлюцинациям.
* **Управляемость:** точность следования инструкциям (форматы JSON, ролевые сценарии, негативные ограничения).
* **Производительность:** скорость генерации (tokens/sec, TTFT).
* **Потребление ресурсов:** пиковая утилизация VRAM и системной RAM.

## Структура репозитория

```
├── PLAN.md              # календарный план
├── requirements.txt     # зависимости
├── configs/
│   └── matrix.yaml      # матрица экспериментов: модели, квантизации, параметры генерации
├── data/                # тестовые наборы: промпты на фактологию, JSON, роли, ограничения
├── src/                 # общий код: запуск модели, метрики, замер VRAM и TTFT
├── scripts/             # точки входа: скачать модели, прогнать оценку, построить графики
├── results/
│   ├── raw_logs/        # сырые ответы и замеры, по файлу на прогон (в git не попадают)
│   └── tables/          # сводные таблицы
├── figures/             # графики для статьи, генерируются скриптом
└── notes/               # источники, методика, наблюдения
```

Правила работы:
* **Веса моделей в git не кладём** — только скрипт скачивания и список сборок в `configs/matrix.yaml`.
* **Сырые результаты руками не правим** — таблицы и графики пересобираются из `results/raw_logs/` скриптом.
* **Каждый прогон записывает свои условия** — модель, квантизация, сид, параметры генерации, версия бэкенда и железо пишутся в тот же файл, что и результат.

## Установка

```bash
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```
