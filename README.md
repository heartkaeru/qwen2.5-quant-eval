# Влияние агрессивной оптимизации и низкобитной квантизации на качество генерации LLM при локальном инференсе (на примере семейства Qwen2.5)

Исследовательский проект, посвященный оценке падения качества генерации и вычислительной эффективности моделей семейства **Qwen2.5** при переходе к низкобитной квантизации и агрессивным техникам оптимизации инференса.

## Цель исследования
Определить границу («sweet spot») между экономией аппаратных ресурсов (VRAM, задержка) и деградацией генеративных способностей языковой модели в сценариях локального развертывания.

## Исследуемые параметры

### Объект исследования
* Семейство моделей **Qwen2.5** (базовые FP16/BF16 vs квантованные варианты: AWQ, GPTQ, GGUF Q8_0, Q4_K_M, суб-3-bit).

### Критерии оценки
* **Качество текста:** фактологическая корректность, семантическая связность ответов, устойчивость к галлюцинациям.
* **Управляемость:** точность следования инструкциям (форматы JSON, ролевые сценарии, негативные ограничения).
* **Производительность:** скорость генерации (tokens/sec, TTFT).
* **Потребление ресурсов:** пиковая утилизация VRAM и системной RAM.

## Структура репозитория

```
├── PLAN.md              # календарный план
├── requirements.txt     # зависимости
├── configs/
│   └── matrix.yaml      # матрица экспериментов: модели, квантизации, параметры генерации
├── data/                # тестовые наборы: промпты на фактологию, JSON, роли, ограничения
├── src/                 # общий код: запуск модели, метрики, замер VRAM и TTFT
├── scripts/             # точки входа: скачать модели, прогнать оценку, построить графики
├── results/
│   ├── raw_logs/        # сырые ответы и замеры, по файлу на прогон (в git не попадают)
│   └── tables/          # сводные таблицы
├── figures/             # графики для статьи, генерируются скриптом
└── notes/               # источники, методика, наблюдения
```

Правила работы:
* **Веса моделей в git не кладём** — только скрипт скачивания и список сборок в `configs/matrix.yaml`.
* **Сырые результаты руками не правим** — таблицы и графики пересобираются из `results/raw_logs/` скриптом.
* **Каждый прогон записывает свои условия** — модель, квантизация, сид, параметры генерации, версия бэкенда и железо пишутся в тот же файл, что и результат.

## Оптимизация и проверка качества (llama.cpp)

Скрипт сохраняет реальные замеры и ответы по каждому профилю в `results/raw_logs/`. Для трёх готовых профилей с JSON-кейсами:

```bash
python scripts/test_optimization.py --model-path models/qwen2.5-3b-q4_k_m.gguf --profiles baseline aggressive aggressive_q4 --cases-jsonl data/quality_cases.jsonl
```

Чтобы изолировать влияние типа KV-кэша, запустите согласованное сравнение FP16/Q8_0/Q4_0 при общем контексте 1024 и включённом FlashAttention:

```bash
python scripts/test_optimization.py --model-path models/qwen2.5-3b-q4_k_m.gguf --kv-ablation-context 1024 --cases-jsonl data/quality_cases.jsonl
```

Mock-режим не создаёт файлы результатов. Пошаговая проверка CUDA и Tesla T4 описана в [notes/colab_t4.md](notes/colab_t4.md); зафиксированная методика — в [notes/methodology.md](notes/methodology.md).

## Установка

### Быстрый запуск в Google Colab

Откройте [ноутбук](notebooks/qwen25_colab.ipynb) через **Colab → Файл → Загрузить блокнот**,
выберите GPU в настройках среды выполнения и запускайте ячейки сверху вниз.
Репозиторий загружать в Colab не нужно.

Ноутбук сравнивает Qwen2.5-3B-Instruct в FP16, bitsandbytes INT8 и bitsandbytes NF4.
В настройках можно выбрать размер модели, число повторов и лимит длины ответа.
Сначала загрузите файл с заданиями: встроенных тестов нет. Ответы сохраняются
во временную папку Colab, а в конце скачивается ZIP с JSON, CSV, графиком и
сведениями о стенде. Drive не используется. Имя прогона создаётся по времени
запуска и настройкам. Пока файлы текущего сеанса доступны, готовые задания можно
пропустить при повторном выполнении ячейки запуска.

Свои задания пишите в [data/prompts.jsonl](data/prompts.jsonl): один JSON-объект
на строку. В файле 20 примеров, включая задания с ручными критериями оценки.
Формат и рекомендации описаны в [инструкции](data/README.md). Проверьте файл
командой `python3 scripts/validate_dataset.py`, затем загрузите этот JSONL
в ячейке с тестами. Ручные задания экспортируются
в `manual_review.csv` и не входят в процент автоматического прохождения.

Это стартовый стенд: AWQ, GPTQ и GGUF пока не включены. Пробные задания нужно
расширить для статьи; их доля успешных ответов не является общей оценкой качества
генерации. VRAM измеряется как пиковая выделенная память PyTorch при генерации,
а RAM — как RSS процесса, измеряемый с интервалом 50 мс.

### Локальное окружение

```bash
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```
